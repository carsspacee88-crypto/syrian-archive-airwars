# نتيجة قياس محرك الجمع V4

## ما الذي يقيسه الاختبار؟

يشغّل `scripts/benchmark_v4_offline.py` أثرًا حتميًا من `1,500` مصدر على ساعة منطقية؛ أي إنه لا ينتظر الإنترنت ولا يتأثر بتذبذب الجهاز. الأثر ثابت بالبذرة `4040150` ويحتوي:

| المسار | العدد |
|---|---:|
| Facebook public embed | 750 |
| X/Twitter oEmbed | 573 |
| مواقع عامة موزعة على 24 مضيفًا | 177 |

| نتيجة الطلب | العدد |
|---|---:|
| HTTP 200 | 1,325 |
| HTTP 403 فردي | 140 |
| HTTP 429 مع `Retry-After: 1.25` | 24 |
| مهلة كاملة 3 ثوانٍ | 11 |

يقارن الاختبار نموذج العطل الموجود في V3 — النوم أثناء حيازة تصاريح المضيف والعامل العام والتأخير المتضاعف — مع جدولة V4 العادلة، وحجز معدل الطلب قبل التصاريح، وكلفة الحفظ المنفصلة.

## النتيجة الحتمية

| القياس | نموذج انهيار V3 | نموذج V4 |
|---|---:|---:|
| زمن الأثر الكامل | 3,902.750ث | 31.460ث |
| الإنتاجية | 23.06 عنصر/دقيقة | 2,860.79 عنصر/دقيقة |
| P90 لمدة العنصر | 481.853ث | 5.931ث |
| P95 لانتظار المجدول | 497.514ث | 7.125ث |
| خدمة الحفظ المجمعة | 12.000ث | 2.250ث |
| نوم مع حيازة تصريح عام | 6,133.508 تصريح·ث | 0 |

عامل المقارنة المنطقي هو `124.05×`. هذا الرقم يثبت إزالة نمط الانهيار من المجدول، ولا يعني وعدًا بأن الإنترنت الحقيقي سيكون أسرع 124 مرة. زمن VPS الفعلي يتأثر بزمن Facebook وX والمواقع الخارجية، DNS، الحجب، وحالة الأرشيف.

## عدالة المسارات في V4

| المسار | أول بدء | P95 انتظار المجدول | أقصى انتظار |
|---|---:|---:|---:|
| Facebook | 0ث | 7.896ث | 8.679ث |
| X/Twitter | 0ث | 5.074ث | 5.132ث |
| المواقع العامة | 0ث | 1.663ث | 1.725ث |

لم ينتظر مسار المواقع العامة خلف كتلة X أو Facebook، واكتملت العناصر `1,500/1,500` في النموذجين مع إبقاء توزيع نتائج الشبكة نفسه.

## بوابات الصحة

نجحت البوابات التسع كلها:

- العدد الدقيق للأثر هو 1,500.
- توجد حالات 200 و403 و429 والمهلة.
- النموذجان أنهيا كل عنصر.
- V4 لا ينام وهو يمسك تصريح العامل العام.
- V4 لا ينام وهو يمسك تصريح المضيف.
- نموذج V3 أعاد إنتاج عيب التصاريح النائمة.
- المواقع العامة لم تتعرض للتجويع.
- V4 خفّض زمن الجدار.
- V4 خفّض P95 لانتظار المجدول.

## إعادة القياس

```bash
python3 scripts/benchmark_v4_offline.py \
  --items 1500 \
  --output data/reports/v4-offline-benchmark.json
```

يعيد التشغيل الملف نفسه بايتًا مقابل بايت عند استخدام العدد والبذرة الافتراضيين. التقرير الآلي الكامل محفوظ في `data/reports/v4-offline-benchmark.json`.

## حدود النتيجة

هذا اختبار جدولة وفشل وحفظ على ساعة منطقية، وليس اختبار سرعة إنترنت ولا إثباتًا لإمكانية استخراج محتوى خاص أو محذوف. النجاح التشغيلي يعني أن المصدر المتعذر لا يوقف بقية المهمة، وأن حالته تُحفظ بدقة؛ ولا يجوز تحويل صفحة محجوبة إلى نجاح وهمي.
