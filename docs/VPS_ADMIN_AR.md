# تشغيل لوحة جمع الأرشيف على VPS

هذه الحزمة تنقل تنفيذ الجمع من تشغيل مؤقت في GitHub Actions إلى خدمة دائمة على VPS. الهاتف يفتح لوحة الإدارة فقط؛ الجمع ينفذه عامل Python داخل الخادم.

## البنية

- **FastAPI + Jinja**: لوحة عربية RTL، تسجيل دخول، إنشاء نطاق، متابعة مباشرة، وإجراءات تحكم.
- **PostgreSQL**: الحالة الدائمة للمهام والعناصر وسجل الأخطاء.
- **Celery + Redis AOF**: طابور مستقل عن خادم الويب. انهيار الواجهة لا يوقف العامل، وانهيار العامل لا يمحو نقطة التقدم.
- **Caddy**: HTTPS تلقائي أمام لوحة الإدارة.
- **SpeedPilotRunner**: محرك الجمع الحالي نفسه، مع قاطع الدائرة، التوازي المحدود بحسب المضيف، cache دائم، وتمرير حي ثم أرشيفي.

فشل حادثة أو مصدر يُحفظ في `collection_items` وتستمر العناصر الأخرى. عطل بنيوي في العامل يغيّر حالة المهمة إلى `failed` مع traceback في `job_events`، ويمكن استئنافها من الملفات المرحلية المحفوظة.

## متطلبات VPS

- Ubuntu 24.04 LTS أو Debian 12.
- 4 إلى 8 vCPU، و8 إلى 16GB RAM، وSSD لا يقل عن 80GB كبداية.
- Docker Engine مع Compose v2.
- اسم نطاق فرعي يشير إلى عنوان VPS، مع فتح TCP 80/443 وUDP 443.
- لا يُنصح بكلمة مرور SSH دائمة؛ استخدم مفتاح SSH مؤقتًا ومستخدم نشر غير root مع sudo.

## الإعداد الأول

```bash
cp .env.vps.example .env.vps
mkdir -p secrets
python -m venv .venv-vps
. .venv-vps/bin/activate
pip install -r requirements-vps.txt
python -m control_plane.cli hash-password > secrets/admin_password_hash
openssl rand -base64 48 > secrets/postgres_password
openssl rand -base64 48 > secrets/session_secret
chmod 600 .env.vps secrets/*
sudo chown -R 10001:10001 data
docker compose -f compose.vps.yaml up -d --build
```

عدّل `ARCHIVE_DOMAIN` في `.env.vps` قبل التشغيل. أمر `legacy-init` يعيد تجميع أجزاء `site-package` ويتحقق من SHA-256 قبل أن يبدأ الويب أو العامل.

## التشغيل اليومي

1. افتح `https://ARCHIVE_DOMAIN/admin/login`.
2. أنشئ مهمة وحدد أول وآخر حادثة.
3. اختر جمع الحوادث، المصادر، والتقرير.
4. راقب العدادات والسجل. تستطيع طلب الإيقاف المؤقت أو الإلغاء؛ يستجيب العامل عند نهاية الدفعة الحالية.
5. استخدم «إعادة الفاشل فقط» بعد إصلاح سبب الحجب أو المهلة.

لا تبدأ الحزمة أي جمع تلقائيًا عند الإقلاع. إنشاء مهمة من اللوحة هو الإجراء الوحيد الذي يرسلها إلى الطابور.

## النسخ الاحتياطي والتحديث

- انسخ يوميًا: مجلد `data/`، وقاعدة PostgreSQL عبر `pg_dump`، وأحجام Redis إذا كانت هناك مهام نشطة.
- حدّث الكود عبر فرع وPull Request، ثم شغّل الاختبارات قبل `docker compose ... up -d --build`.
- لا تجعل عامل الجمع يدفع مباشرة إلى GitHub. راجع النتائج وابنِ الموقع، ثم نفّذ مزامنة Git منفصلة قابلة للتدقيق.

## حدود المرحلة الأولى

- قاعدة البيانات تُنشأ تلقائيًا؛ قبل تغييرات مخطط مستقبلية يجب إضافة Alembic migrations.
- يوجد عامل Celery واحد عمدًا لمنع مهمتين من الكتابة في ملفات البيانات نفسها. التوازي الشبكي الداخلي يبقى 6 افتراضيًا مع عامل واحد لكل hostname.
- الـVPS لا يتجاوز تسجيل الدخول أو الحظر أو شروط المواقع. فائدة النظام هي الاستمرارية، cache، المراقبة، والاستئناف؛ لا ضمان لاستخراج نص كل رابط.
- هدف 8:50 للنطاق 0151–1000 يمكن تطبيقه على فهرسة الحوادث والروابط وحالاتها، لكن جلب نصوص 12,450 مصدرًا خارجيًا كاملة يحتاج إثراءً غير متزامنًا ما لم تتوفر نسخة WARC/cache محلية مسبقًا.
