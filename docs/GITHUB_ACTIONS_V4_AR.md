# تشغيل محرك الجمع V4 على GitHub Actions

## النتيجة

أصبح محرك الجمع `4.1.0` قابلًا للتشغيل داخل مستودع الأرشيف السوري من دون
PostgreSQL أو Redis أو Celery. هذه الخدمات تبقى مناسبة للوحة VPS الدائمة،
أما GitHub Actions فيستبدلها بحالة JSON ذرية قابلة للاستئناف ومشمولة بتاريخ
Git.

يمر التشغيل الناجح بالتسلسل التالي:

1. فحص الاختبارات.
2. إعادة تكوين لقطة الموقع التاريخية والتحقق من بصمتها.
3. إنشاء بيان النطاق وجمع الحوادث.
4. جمع نصوص المصادر من روابط الأرشيف المعروفة فقط، من دون فتح الرابط الأصلي.
5. حفظ المتعذر الخارجي في طابور الاسترداد الدائم.
6. توليد التقارير وبناء جميع صفحات الموقع والتحقق منها.
7. دفع `data/` إلى `main`.
8. إطلاق نشر GitHub Pages عبر `workflow_run` بعد نجاح سير الجمع.

## التشغيل من GitHub

افتح **Actions → جمع بيانات Airwars → Run workflow**.

| الحقل | المعنى | الافتراضي |
| --- | --- | --- |
| `operation` | `collect` لجمع النطاق أو `recover` لاسترداد مؤجله | `collect` |
| `first_sequence` | أول تسلسل في النطاق | `263` |
| `last_sequence` | آخر تسلسل في النطاق | `1000` |
| `workers` | الحد العالمي للمهام الشبكية | `64` |
| `per_host_workers` | التوازي داخل المضيف الواحد | `1` |
| `delay` | الفاصل الأدنى داخل المضيف | `0.75` ثانية |
| `source_batch_size` | المصادر في كل دفعة داخل التشغيل | `1000` |
| `recovery_limit` | عناصر الاسترداد في تشغيل واحد | `500` |

لا تشغّل عمليتي جمع متوازيتين؛ مجموعة `airwars-v4-collector` تمنع التداخل
وتترك التشغيل الأقدم ينتهي بدل إلغائه.

### التشغيل بلا GitHub CLI أو تسجيل OAuth محلي

ملف التحكم هو `.github/v4-request.json`. أي التزام يغيّر هذا الملف على
`main` يشغّل V4 تلقائيًا. مثال طلب جمع:

```json
{
  "schema_version": 1,
  "request_id": "collect-0263-1000-archive-only-r1",
  "operation": "collect",
  "first_sequence": 263,
  "last_sequence": 1000,
  "workers": 64,
  "per_host_workers": 1,
  "delay": 0.75,
  "source_batch_size": 1000,
  "recovery_limit": 500
}
```

يجب تغيير `request_id` في كل طلب مقصود. يقرأ سير العمل نسخة الملف من SHA
الذي أطلق الحدث، لكنه يجمع فوق أحدث بيانات `main` عند بدء دوره؛ لذلك لا
يضيع الطلب الأصلي ولا تُهمل نتيجة تشغيل سبقه. لا تؤدي التزامات `data/`
التي ينشئها الجامع إلى حلقة تشغيل جديدة لأن مشغّل `push` محصور بمسار ملف
الطلب. إذا بلغ التشغيل ميزانية الوقت، يحفظ نقطة الاستئناف ويطلق تشغيلًا
جديدًا للنطاق نفسه تلقائيًا. يبقى `started_at` الأول محفوظًا، ولا يُسجل
`finished_at` النهائي إلا بعد حسم الحادثة الأخيرة؛ لذلك يقيس التقرير المدة
الإجمالية عبر كل التشغيلات، لا مدة Job واحد فقط.

لا يعتمد نشر Pages على حدث `push` الناتج عن `GITHUB_TOKEN`؛ ينتظر سير
`نشر الأرشيف على GitHub Pages` اكتمال `جمع بيانات Airwars` بنجاح عبر
`workflow_run` ثم ينشر أحدث حالة من `main`.

## دلالة النجاح

اكتمال المهمة يعني أن كل حوادث النطاق وكل مصادرها حُسمت بنوع من الأنواع
التالية:

- نص محفوظ من رابط أرشيف معروف فقط.
- عنصر مكتمل بالسياسة، مثل رابط وسائط ثنائي لا يسمح المشروع بتنزيله.
- عنصر خارجي مؤجل موجود في طابور الاسترداد.

لذلك يمكن أن تكون المهمة ناجحة بنسبة تشغيل 100٪، مع تغطية نصية أقل من
100٪. يظهر الرقمان منفصلين في تقرير `v4-action-XXXX-YYYY.json`.

## الحالة الدائمة

| المسار | المحتوى |
| --- | --- |
| `data/pilot/speed-pilot-XXXX-YYYY-manifest.json` | هويات حوادث النطاق |
| `data/pilot/speed-pilot-XXXX-YYYY-progress.json` | نقاط تقدم الحوادث والمصادر والقياسات |
| `data/recovery/v4-XXXX-YYYY.json` | المتعذر الخارجي وسجل ما استُرد |
| `data/cache/source-url-index.json` | فهرس النصوص والروابط المسترجعة سابقًا |
| `data/incidents/` | JSON الحوادث الموحّد |
| `data/sources/` | النصوص الأصلية وحالة كل مصدر |
| `data/reports/v4-action-XXXX-YYYY.*` | ملخص تشغيل Action |

كل كتابة حرجة ذرية: يُكتب ملف مؤقت ثم يُستبدل الملف النهائي. عند فشل خطوة
بعد بدء الجمع يحاول سير العمل دفع نقطة استئناف برسالة تبدأ
`data: checkpoint V4`، ولا تنشر GitHub Pages هذه النقطة غير المتحققة.

## الاسترداد

اختر العملية `recover` وأدخل النطاق نفسه. يعيد V4 محاولة الروابط المؤرشفة
المدرجة، ثم يبحث عن أحدث لقطة Wayback القابلة للاستخدام، من دون فتح الرابط
الأصلي في أي مرحلة. يبقى
العنصر في الطابور إن كان العائق خارجيًا، ويُحذف منه فقط بعد حفظ نص أو حسمه
بالسياسة.

## السياسات الثابتة

- الترجمة الآلية معطلة.
- لا تُنزّل صور أو فيديوهات أو صوتيات.
- يمنع طلب Facebook وX والمواقع الأصلية، ويمنع التحويل الشبكي من مضيف
  أرشيف إلى مضيف غير أرشيفي قبل إرسال الطلب الثاني.
- لا تُخزّن ملفات PDF أو Office الثنائية؛ يُحفظ النص والبيانات الوصفية فقط.
- لا يُعد نجاح HTTP اكتمالًا إذا أخفق استخراج النص.
- لا يُحذف النص القديم عند تعارض نسخة أحدث معه؛ تبقى المتغيرات والمنشأ
  للمراجعة.
